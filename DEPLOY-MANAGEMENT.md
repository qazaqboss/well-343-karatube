# Задание: поднять subsoil-management рядом с nanocem-app

Одна задача: развернуть второе приложение (контроль лицензионных обязательств) в том же проекте
Railway, где уже живёт сайт nanocem.app, дать ему базу Postgres и адрес `erp.nanocem.app`.
Ничего из того, что уже работает, не трогаем.

## Справочные данные

| Что | Значение |
|---|---|
| Репозиторий | `qazaqboss/subsoil-management`, ветка `main` |
| Root Directory | пусто (корень) — в нём Dockerfile, собирающий фронт и бэк вместе |
| Переменные | `DATABASE_URL`, `SECRET_KEY`, `ANTHROPIC_API_KEY` |
| База | Railway PostgreSQL, имя сервиса `postgres-management` |
| Healthcheck | `/api/health`, таймаут 120 |
| Адрес | `erp.nanocem.app` — CNAME в Cloudflare, Proxy status DNS only |

## Что стоит знать

- **Миграции не нужны.** При старте приложение само вызывает `Base.metadata.create_all` и заливает
  демо-записи, если таблицы пустые. Первого пользователя заводить не требуется.
- **Фронтенд отдельным сервисом не разворачиваем.** Корневой Dockerfile собирает React в статику
  и кладёт её внутрь образа с FastAPI, с пустым `VITE_API_URL` — приложение обращается к своему же
  домену. Отдельный сервис и переменная с адресом API всё сломают.
- **`REDIS_URL` не нужен** — он есть в примере `.env`, но приложение поднимается без него.
- **Домен привязывается к одному сервису**, поэтому второе приложение получает поддомен, а не
  корневой `nanocem.app`.
