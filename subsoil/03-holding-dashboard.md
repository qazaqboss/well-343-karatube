# 03. Сводка холдинга — главный экран руководства

Задача экрана: за 2 минуты ответить руководителю на три вопроса —
1. **Что мы добыли и как это по сравнению с планом и вчера?**
2. **Где проблемы, требующие решения сегодня?**
3. **Какие требования (обязательства, отчёты, лицензии) горят?**

## 2. Блоки

### 2.1. «Внимание сегодня»
Лента из 4–8 пунктов, собирается правилами (таблица `alert_rules`). Порядок: критично → внимание. Клик ведёт к источнику.

| Правило | Условие | Уровень |
|---|---|---|
| Обязательство просрочено | `obligation.due_date < today` и не выполнено | критично |
| Срок отчёта ≤ 7 дней | `reporting_event.due_date - today ≤ 7` | внимание |
| Лицензия/контракт истекает ≤ 90 дней | `contract.valid_to - today ≤ 90` | внимание |
| Рост обводнённости | `Δ water_cut (сутки) > 5 п.п.` | внимание |
| Падение нефти по скважине | `Δ oil (сутки) < −20 %` | внимание |
| Скважина в простое | `status = stopped` > 24 ч | внимание |
| Команда не исполнена | `command.status ≠ done` > 24 ч | внимание |
| План добычи | факт месяца к дате < 90 % | внимание |

Пороги редактируются в `/app/settings/thresholds`.

### 2.2. Карточки KPI (5 штук)

| KPI | Формула | Сравнение |
|---|---|---|
| Нефть, т/сут | `Σ Q_oil` по последнему замеру каждой работающей скважины | к вчера, % плана |
| Жидкость, м³/сут | `Σ Q_liq` | к вчера |
| Обводнённость, % | `Σ Q_water / Σ Q_liq × 100` (средневзвешенная, **не** среднее по скважинам) | к вчера, п.п. |
| Фонд | `в работе / всего`, отдельно простой | к вчера |
| Требования | просрочено · в ближайшие 30 дней | — |

Нефть из замера: `Q_oil = Q_liq × (1 − W/100) × ρ_oil`, ρ — из справочника месторождения. Формулы — в `packages/shared/metrics.ts`.

### 2.3. Таблица «Активы»
Строка = месторождение (на уровне холдинга) или скважина (на уровне месторождения). Сортировка по умолчанию — по статусу (красные сверху), затем по нефти. Цветная точка = худший статус строки.

### 2.4. График добычи
90 дней, линия факта + пунктир плана, отметки заходов UT-9 и крупных событий (ГТМ). Переключатель: нефть / жидкость / обводнённость.

### 2.5. Эффект NanoCem UT-9
Число заходов, суммарный прирост нефти (т/сут), доля успешных. Прирост = средний дебит 14 сут после − 14 сут до захода.

### 2.6. Требования на 30 дней
Объединённый список из `obligations` и `reporting_events`, сортировка по сроку.

## 3. Обновление данных

- Показатели промысла — в реальном времени (WebSocket от OFI) + полный пересчёт в 06:00 для утренней сводки.
- Требования — пересчёт статусов раз в час и при любом изменении.
- Снимок сводки на 06:00 сохраняется (`daily_snapshots`) — для истории и отправки в Telegram/почту руководству.
