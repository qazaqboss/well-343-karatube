# 04. Модули кабинета

Каждый модуль — отдельный раздел `/app/<модуль>` и отдельный NestJS-модуль в `apps/api`. Все пишут в общую БД и отдают показатели в сводку через `holding`-модуль.

---

## 4.1. Промысел (бывший OilField Interact)

**Источник:** сервис на Railway `ofiapi-production`. Код и БД переносятся как есть, меняется бренд и навигация.

**Что делает** (без изменений по логике OFI):
- общая карточка записи по скважине: блоки «Замер» (полевик), «Действие» (супервайзер), «Оценка» (технолог);
- автоматический расчёт «до/после»;
- утренняя сводка за ночь, проблемные скважины сверху;
- команды руководителя: создана → принята → выполнена → подтверждена замером;
- офлайн-очередь на телефоне.

**Что добавить для Subsoil:**
- поле `company_id` у месторождения (иерархия холдинга);
- таблица `production_plans` (план по месторождению на месяц);
- событие `measurement.created` → пересчёт KPI сводки;
- ссылка из карточки скважины на заходы UT-9 и на контракт.

**Отдаёт в сводку:** нефть, жидкость, обводнённость, фонд, простои, неисполненные команды.

## 4.2. NanoCem UT-9

**Источник:** страницы nanocem.app `plan`, `sealing`, `water-cut`, `product`.

**Экраны:**
- **Обзор** — заходы, прирост дебита, доля успешных, вклад в обводнённость фонда.
- **Программа** — портфель кандидатов, сценарии применения, волны заходов.
- **Герметичность** — результат изоляции по заходам, АКЦ/ЭМДС, отказы.
- **Заход** — карточка работы: интервал, объём и рецептура смеси, акт, дебит до/после.

**Новое:**
- **Скоринг кандидатов** — ранжирование скважин по ожидаемому приросту (обводнённость, дебит жидкости, состояние цемента, история ГТМ). Сначала правила, потом модель.
- **Дизайн заливки** — расчёт объёма смеси под интервал (формулы — `TODO:` от технолога UT-9).

**Отдаёт в сводку:** число заходов, прирост т/сут, доля успешных.

## 4.3. Недропользование (требования)

**Источник:** nanocem.app `/erp/`, `/stages.html`, `/ai` + наработки SubsoilERP (карта отчётности, вики по 7 этапам).

**Экраны:**
- **Обзор** — светофор по каждому контракту: этап, обязательства, просрочки, ближайший срок.
- **Контракты и лицензии** — номер, недропользователь, срок действия, этап, участок.
- **Обязательства** — реестр: что, по какому контракту, срок, ответственный, статус, документ-подтверждение.
- **Карта отчётности** — орган, форма, периодичность, крайний срок, портал подачи, статус. Модель — по **типу триггера** (ежесуточно / ежемесячно / ежеквартально / событийно), а не по органу.
- **Календарь** — все сроки на месяц.
- **Этапы** — 7 этапов недропользования: что делается, какие документы, какой отчёт.

**Логика статусов обязательства:**

| Статус | Условие |
|---|---|
| `done` | приложен документ-подтверждение и отмечено «выполнено» |
| `overdue` | `due_date < today` и не `done` |
| `due_soon` | `due_date − today ≤ 30` |
| `planned` | остальное |

**Отдаёт в сводку:** просроченные обязательства, сроки на 30 дней, истекающие контракты.

## 4.4. Отчёты

Генерация из тех же данных, без повторного ввода:

| Отчёт | Формат | Источник |
|---|---|---|
| Суточная сводка руководству | PDF, Telegram | `daily_snapshots` |
| Отчёт по этапу недропользования | PDF | контракт + обязательства + документы |
| Паспорт скважины | PDF | скважина + замеры + заходы |
| Эффект UT-9 за период | PDF, XLSX | заходы + замеры |
| Реестр обязательств | XLSX | обязательства |

Генерация — в `worker` (BullMQ), файлы — в S3-совместимом хранилище.

## 4.5. AI-помощник

Два источника ответов:
1. **Нормативка** — КоНН РК, Экологический кодекс, правила отчётности. RAG по вики (заметки по 7 этапам), без дообучения: нормы меняются, переиндексация дешевле.
2. **Факты холдинга** — через инструменты (function calling) к API: «какие обязательства просрочены», «добыча Каратюбе за неделю», «где выросла вода».

Ограничения: ассистент видит только данные компаний пользователя; каждое число в ответе — со ссылкой на экран-источник.
