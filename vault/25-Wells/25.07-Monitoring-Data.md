# Данные мониторинга

## Источник

Суточные режимные листы по каждой скважине: дебит нефти (Qн, т/сут), дебит жидкости
(Qж, м³/сут), обводнённость (%), обороты насоса (об/мин), динамический уровень (Ндин, м)
и комментарий смены — остановки, замеры, ремонты, изменения режима.

## Где это живёт на платформе

| Слой | Что показывает |
|---|---|
| Страница скважины | полная история: график, лента событий, журнал замеров с фильтрами по фазам |
| `wells.js` | единый источник статусов фонда: одна правка обновляет все страницы |
| Страница герметичности | итог изоляции по шести заходам и разбор АКЦ |
| Страница программы | портфель кандидатов на следующие заходы |
| ERP | контракты, скважины, паспорта, дедлайны — и генерация отчётов |

## Фазы в журнале

`before` — до РИР · `krs` — капитальный ремонт / закачка раствора · `after` — после РИР ·
`forced` — форсированный режим · `stable` — стабильная работа · `restart` — вывод на режим
после ремонта · `idle` — простой. Дни ремонта из графиков исключаются, чтобы не рвать динамику.

## Глубина данных

Суточные замеры ведутся с 01.01.2026 (по 343 — с 15.01), последний загруженный месяц —
**сентябрь 2026, по 27.09**. Объём: 254–269 суток на скважину, из них с замером добычи
154–249 в зависимости от простоев.

Исходники месяцев лежат в корне репозитория markdown-файлами вида
`karatube_skvazhiny_sentyabr_2026.md` — из них данные переносятся в массив `DATA` на странице
скважины, а сводные статусы — в `wells.js`.

## Связь с отчётностью недропользователя

Фонд стоит на [[20.05.00-Overview|Этапе 5]]. Те же суточные данные ложатся в:

- **паспорт скважины** — конструкция, интервалы, режим, история ремонтов
- **отчёт по этапу** — фактическая добыча против проектной
- **анализ разработки** — не реже 1 раза в 3 года, [[20.03.00-Overview|Этап 3]]

Отдельно собирать цифры под отчёт не нужно — они уже есть в системе.
