# Railway: собрать всё в проект `nanocem` — сценарий для Claude в Chrome

Задача: один проект Railway, внутри — все приложения и их базы, домен и ключи на месте.
Работа идёт в группе вкладок; скопируйте промпт целиком в Claude в браузере.

## Итоговая схема

| Сервис в проекте `nanocem` | Источник | Что отдаёт | Адрес |
|---|---|---|---|
| `nanocem-app` | `qazaqboss/well-343-karatube`, Dockerfile в корне | сайт аналитики + AI-помощник `/ai` + ERP `/erp/` | `nanocem.app` |
| `subsoil-management` | `qazaqboss/subsoil-management`, Dockerfile в корне (собирает React-фронт и FastAPI разом) | контроль лицензионных обязательств | `erp.nanocem.app` |
| `postgres-management` | Railway Postgres | база для subsoil-management — **обязательна** | внутренний |
| `postgres-nanocem` | Railway Postgres | про запас для nanocem-app — **код её пока не использует** | внутренний |

| Что | Значение |
|---|---|
| Целевой проект | `nanocem` (тот, где сейчас сервис `subsoil-ai`) |
| Основной репозиторий | `qazaqboss/well-343-karatube`, ветка `main` |
| Второе приложение | `qazaqboss/subsoil-management`, ветка `main`, Root Directory — корень |
| Переменные `nanocem-app` | `ANTHROPIC_API_KEY`, `DB_PATH=/data/erp.db` |
| Переменные `subsoil-management` | `DATABASE_URL`, `SECRET_KEY`, `ANTHROPIC_API_KEY` |
| Том | `/data` у `nanocem-app` |
| Домены | `nanocem.app` → `nanocem-app`, `erp.nanocem.app` → `subsoil-management` |
| DNS | Cloudflare (nameservers переведены), регистрация домена — Vercel |

## Что важно знать

- **Postgres для `nanocem-app` создаётся на вырост.** Код ERP сейчас работает с SQLite на томе
  `/data`. Пока не переписан слой доступа к данным, база будет простаивать и просто стоить денег.
  Перевод ERP на Postgres — отдельная задача по коду, не для браузерного агента.
- **`subsoil-management` без Postgres не поднимется** — там SQLAlchemy и psycopg2, приложение
  ждёт `DATABASE_URL` при старте.
- **Тома между проектами и сервисами не переносятся.** Новый том создаётся пустым; для ERP это не
  страшно — стартовая база копируется из репозитория автоматически, но данные, введённые в ERP
  после деплоя, живут только на своём томе.
- **Домен привязывается к одному сервису.** Поэтому второе приложение получает поддомен.
- **Удаление проекта необратимо** — уносит сервисы, тома и историю деплоев.
